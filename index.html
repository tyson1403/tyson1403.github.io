Case study: moving 600+ Cypress tests to Playwright

How I used a supervised AI migration agent to move a large monorepo test suite off Cypress.

600+ tests in the largest project · 3 spec files per batch · human review on every batch

The problem

Cypress has no native parallelisation, so we used the cypress-split plugin to spread specs across CI runners. With about 500 tests across all projects, that worked well. As the products grew, every project passed 200 tests and the largest passed 600. At that size, the setup stopped scaling.

  • Growing suites meant adding more runners to the pipeline.
  • If one runner got stuck, the whole pipeline stalled with it.
  • Runs kept runners busy for 30–40 minutes, which delayed development deployments because we work in a monorepo.
The approach

Playwright handles parallel runs natively, so we could retire Cypress entirely and drop the split plugin. Rather than rewrite hundreds of tests by hand, we built an AI agent to perform the migration, with a human reviewing every step.

  • The agent worked on three spec files at a time, together with the helper methods they depend on.
  • Working in validated batches kept every change reviewable, with human review and the existing CI quality gates applied before anything was merged.
  • Failing migrated tests were repaired with Playwright MCP and its self-healing loop.
  • I reviewed each batch and fixed remaining problems directly before moving on.
What went wrong

My first attempt was to ask the agent to migrate the entire project in one go: more than 600 tests plus all their supporting methods. The agent kept getting stuck and consumed a large number of tokens.

I switched to a few files and their related methods at a time. It needed more hands-on supervision, but it was the more effective and efficient route.

The outcome
  • The 600+ test project was migrated in controlled, validated batches, each reviewed before merging.
  • Cypress was retired completely, and the split plugin is no longer needed.
  • Load on the CI runners and the pipeline dropped. I set the Playwright worker count equal to the previous number of runners to limit flakiness, so run times stayed about the same.
  • Using Playwright MCP and its self-healing loop to fix failing tests improved reliability, which I estimate raised overall test quality by around 30%.
  • The Playwright framework is now the standard for new projects, including Production Planning and Order Management.

Lesson: keep AI work in small, verifiable units and keep a human in the review loop.
